# 输出范围与 Token 控制

## 一、基本原则

1. 默认 `standard`，不自动使用 `deep`；
2. 用户只要求一个结果时，只执行一个模式；
3. 不复述材料全文，不重复用户已经提供的内容；
4. 优先输出判断、依据、问题和修改动作；
5. 表格只用于比较、矩阵和对齐，不把所有内容都表格化；
6. 材料不足时明确停止，不用长篇推测填满模板；
7. 流程模式按阶段交付中间产物，但避免重复展示同一信息；
8. 用户明确要求可直接提交的正文时，才生成完整正文。

## 二、模式边界

| 用户需求 | 使用模式 | 默认不输出 |
|---|---|---|
| 判断是否值得读 | `quality quick` | 完整论文解析、文献卡 |
| 解析一篇论文 | `paper standard` | 完整评分、Obsidian YAML |
| 只要文献卡 | `obsidian` | 长篇评论 |
| 生成矩阵 | `review matrix` | 完整综述正文 |
| 写综述段落 | `citation paragraph` | 文献清点和大矩阵 |
| 找选题 | `gap standard` | 完整开题报告 |
| 设计方法 | `method design` | 无关理论综述 |
| 修改开题 | `proposal revise` | 从头生成未要求章节 |
| 优化题目 | `thesis title` | 整篇论文目录和正文 |
| 完整连续任务 | `workflow` | 每阶段重复前文 |

## 三、深度控制

### quick

- 3—6 个核心判断；
- 每个判断给简短依据；
- 结尾只给一个下一步。

### standard

- 覆盖模板的核心栏目；
- 对关键判断标证据；
- 删除与用户目标无关的可选栏目。

### deep

只有在以下情形使用：

- 核心文献精读；
- 方法或理论存在复杂争议；
- 用户要求逐部分严格评审；
- 材料充分，能够支持细致证据定位。

`deep` 沿用标准模板加深，不虚构独立模板文件。

## 四、多篇文献

| 材料数量 | 推荐做法 |
|---:|---|
| 1—2 篇 | 单篇事实卡或比较分析，不称系统综述 |
| 3—8 篇 | `review standard`，可同时完成聚类与矩阵 |
| 9—20 篇 | 先事实账本和矩阵，再分类综述 |
| 20 篇以上 | 分批生成事实卡，先去重和筛选，再聚类；不逐篇长评 |

数量不是唯一标准。摘要材料较多但信息不完整时，应降低结论强度。

## 五、流程模式压缩

每阶段只保留：

```text
本阶段目标
核心产物
关键依据
未解决问题
阶段状态
下一阶段交接数据
```

最终报告引用中间产物，不完整复制各阶段内容。

## 六、修改任务

修改用户文本时：

1. 先判断结构问题还是语言问题；
2. 结构问题优先修复逻辑与证据；
3. 保留有效观点和用户语气；
4. 不因“润色”新增事实、理论或文献；
5. 用户只要求局部修改时，不擅自重写全文。

## 七、停止条件

出现以下情况时，简要说明并停止扩写：

- 核心材料缺失；
- 引用身份无法确认；
- 研究问题没有数据来源；
- 用户要求的因果或效果结论不受方法支持；
- 所需下一阶段必须依赖尚未提供的事实。
