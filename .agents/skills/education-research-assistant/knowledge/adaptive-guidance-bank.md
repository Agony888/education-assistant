# 自适应引导问题库

## 一、目标

本文件用于 `workflow guided`。它不提供固定问卷，而是根据目标工作流、用户已有信息和前一轮回答，动态选择下一项最关键问题。

核心原则：

```text
不重复已知信息
→ 不询问尚未影响决策的次要信息
→ 每轮只解决一个关键不确定点
→ 回答改变研究路径时立即更新后续问题
```

## 二、问题优先级评分

候选问题按以下维度判断优先级：

| 维度 | 说明 | 高优先级情形 |
|---|---|---|
| 路径影响 | 是否会改变工作流、研究类型或方法 | 会改变调查/案例/文本分析选择 |
| 阻断程度 | 不回答是否无法继续 | 不知道研究对象、数据来源 |
| 冲突程度 | 当前信息是否互相矛盾 | 想研究效果但没有实验条件 |
| 信息增益 | 回答后能否同时解决多个问题 | 明确可接触样本可决定方法和范围 |
| 用户负担 | 是否容易回答 | 优先问具体事实，后问抽象判断 |

优先顺序：

```text
阻断性冲突
→ 目标与边界
→ 数据和现实条件
→ 研究类型
→ 理论与维度
→ 工具细节
→ 格式要求
```

## 三、通用分支规则

### 1. 用户已有完整题目

不要先问“你想研究什么”。优先检查：

1. 题目中的核心研究对象是什么；
2. 题目是否预设因果或效果；
3. 用户能获得什么数据；
4. 题目中的关键概念是否已有来源。

### 2. 用户只有大致方向

按以下顺序：

```text
真实问题
→ 研究对象
→ 场域与范围
→ 可获取材料
→ 研究目标
→ 题目表达
```

### 3. 用户无法回答理论问题

不要追问“你准备采用什么理论”。改问：

- 你希望解释教师为什么使用或不使用某项技术吗？
- 你更关注能力构成、行为过程，还是外部条件？
- 你的问卷维度已有文献来源吗？

再由 Skill 判断是否需要 TAM、TPACK、教师专业发展理论或文献归纳框架。

### 4. 用户选择“不确定”

记录为暂定，不连续追问同一问题。先转向其他可确认事实；若其成为阻断项，再用更具体的选项重新询问。

### 5. 用户答案改变研究类型

立即更新：

- 后续问题清单；
- 方法建议；
- 数据需求；
- 目录类型；
- 已有决策中受影响的内容。

## 四、`proposal-design` 与 `thesis-design` 问题分支

### 阶段 A：研究中心

候选问题：

```text
你最想解决的核心问题更接近哪一种？

A. 描述当前状况
B. 解释问题和原因
C. 分析一类文本或教学材料
D. 记录并改进一项教学实践
E. 检验某种做法是否有效
F. 暂时不确定
```

分支：

- A/B：优先调查研究或混合研究；
- C：优先文本分析；
- D：优先案例、实践探索或行动研究；
- E：继续确认实验、前后测或对照条件。

### 阶段 B：研究对象与范围

优先确认：

- 教师、学生、课堂、教材、作业、反思文本还是政策文件；
- 学科与学段；
- 城乡、学校或区域范围；
- 研究对象数量和可接触方式。

若对象范围过大，提供缩小选项，不直接替用户决定。

### 阶段 C：数据条件

候选问题：

```text
你实际能够稳定获得哪一类材料？

A. 教师问卷
B. 教师访谈
C. 课堂观察或录像
D. 教案、作业、反思等文本
E. 学生成绩或前后测数据
F. 目前没有确定
```

分支规则：

- 只有问卷：不能承担深层原因解释；
- 问卷+访谈：可描述现状并解释部分原因；
- 文本材料：可采用内容分析或编码；
- 前后测/对照：才可考虑效果研究；
- 无稳定数据：优先缩小题目或改为文献/文本研究。

### 阶段 D：概念与维度

不要直接询问“你有几个维度”。先确认：

1. 核心概念是什么；
2. 概念是否有权威或高相关文献来源；
3. 维度是理论维度、文献归纳维度还是问卷操作维度；
4. 每个维度能否对应研究问题和题项。

### 阶段 E：方法与分析能力

根据用户实际能力询问：

- 是否能使用 SPSS 或其他统计工具；
- 是否能完成信效度、描述统计、差异分析、相关或回归；
- 是否能进行编码和主题分析；
- 是否有导师或同伴支持。

不要推荐超出用户条件的复杂模型。

## 五、`literature-review` 问题分支

### 1. 先确认综述用途

- 为选题寻找研究空间；
- 为开题报告写国内外研究现状；
- 为论文某一小节写综述；
- 做独立综述报告。

用途不同，文献边界和最终输出不同。

### 2. 再确认材料状态

- PDF 全文；
- 摘要；
- 用户已有文献卡；
- 只有题录信息。

全文与摘要混合时，降低方法和理论判断强度。

### 3. 文献数量分支

- 1—2 篇：比较分析，不称系统综述；
- 3—8 篇：可直接建立矩阵和主题聚类；
- 9—20 篇：先批量事实卡和筛选；
- 20 篇以上：分批处理，先去重、相关性和质量筛选。

### 4. 综述结构分支

根据研究主题选择：

- 概念—维度—影响因素—测量；
- 技术—场景—主体—条件；
- 理论—方法—发现—不足；
- 发展阶段或时间脉络；
- 国内外比较。

不得默认“国外研究—国内研究—述评”作为唯一结构。

## 六、`paper-to-note` 问题分支

优先确认：

1. 材料是全文还是摘要；
2. 用户是要阅读、筛选还是入库；
3. 是否已有 citekey 和 Obsidian YAML 规范；
4. 是否需要与当前论文选题建立双链。

若用户只需要解析，不启动完整入库流程。

## 七、完成度判断

引导完成度不按问题数量计算，而按关键字段计算：

| 字段 | 权重 |
|---|---:|
| 最终交付物与目标工作流 | 15 |
| 研究对象与边界 | 15 |
| 核心问题 | 15 |
| 数据或材料来源 | 20 |
| 研究类型 | 10 |
| 概念、理论或分析维度 | 10 |
| 方法与分析方式 | 10 |
| 格式与限制 | 5 |

判断：

- 80—100：可以执行；
- 60—79：有条件执行，需标记假设；
- 40—59：只适合生成初步方案；
- 低于 40：继续引导，不生成完整成果。

任何情况下，若“数据或材料来源”为零，不能把研究方案标为完整可行。

## 八、提问语言

问题应使用用户能理解的语言。

不推荐：

> 你的认识论立场与研究范式是什么？

推荐：

> 你更想了解整体情况，还是深入分析少数教师的真实经历？

不推荐：

> 你准备采用何种理论模型？

推荐：

> 你希望重点解释教师的能力构成、技术接受，还是学校支持条件？

## 九、禁止事项

- 不把固定问题清单机械问完；
- 不在已有答案中仍重复追问；
- 不先问理论，再问现实问题；
- 不诱导用户选择 Skill 偏好的研究方法；
- 不因用户选择某方法就默认其具备实施条件；
- 不把完成度分数当作研究质量分数；
- 不用十几个问题一次性轰炸用户。
