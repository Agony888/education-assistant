# 引导式梳理会话模板

## 一、用途

当用户暂时无法一次说清研究题目、研究问题、方法、开题要求或综述需求时，使用 `guided` 模式逐轮梳理。

本模式不是连续输出长篇答案，而是：

```text
确定最终目标
→ 每轮询问一个关键问题
→ 记录并校正用户答案
→ 检查信息是否充分
→ 调用对应模式或流程
→ 一次性生成最终成果
```

## 二、会话状态卡

每轮内部维护以下状态，不必每次完整展示给用户：

```yaml
guided_session:
  target: ""
  status: "进行中"
  current_stage: "目标确认"
  confirmed: {}
  tentative: {}
  skipped: []
  conflicts: []
  missing: []
  next_question: ""
  ready_to_generate: false
  target_mode_or_pipeline: ""
```

状态只使用：

- `目标确认`；
- `信息收集`；
- `关系校验`；
- `等待生成`；
- `已完成`。

## 三、每轮提问规则

1. 每轮只问一个主问题，不在一个回合堆叠多个独立问题。
2. 优先询问最能影响后续方案的缺失信息。
3. 问题应具体、自然、可回答，避免直接要求用户解释复杂理论。
4. 适合时提供 3—6 个选项，并保留“其他”“不确定”“暂时跳过”。
5. 已经回答过的信息不得重复询问；发现矛盾时只核对矛盾点。
6. 用户回答模糊时，先给出你对其含义的简短归纳，再询问是否准确。
7. 不因用户“不确定”而中断，可先记录为待确认并继续询问其他关键项。
8. 除非用户要求查看，不要每轮都输出完整状态表。

推荐提问格式：

```text
目前已经确认：……

接下来只确认一件事：……？

A. ……
B. ……
C. ……
D. 其他
E. 暂时不确定
```

## 四、用户控制指令

用户可随时使用：

| 指令 | 行为 |
|---|---|
| `查看进度` | 展示已确认、待确认和当前完成度 |
| `修改：字段=内容` | 修改已记录信息，并检查受影响项目 |
| `跳过` | 暂时跳过当前问题，记录为待确认 |
| `不确定` | 记录为不确定，不强迫用户作答 |
| `直接生成` | 根据现有信息生成，明确假设和缺口 |
| `重新开始` | 清空当前引导状态，重新选择目标 |
| `结束引导` | 停止提问，只总结已梳理内容 |

## 五、第一问：确定最终目标

用户未明确最终交付物时，第一轮只询问目标：

```text
你希望最后得到什么？

A. 明确并优化论文选题
B. 梳理研究问题、理论、方法和目录
C. 完成开题报告方案
D. 整理多篇文献并形成文献综述
E. 设计问卷、访谈或文本分析工具
F. 评价或修改一份已有论文/开题材料
G. 其他
```

目标确定后设置 `target_mode_or_pipeline`：

| 最终目标 | 目标模式或流程 |
|---|---|
| 选题优化 | `thesis` 或 `gap` |
| 完整论文设计 | `workflow thesis-design` |
| 开题报告 | `workflow proposal-design` |
| 文献综述 | `workflow literature-review` |
| 方法与工具 | `method design` |
| 修改已有材料 | 对应模式 `revise/checklist` |

## 六、不同目标的信息清单

### 1. 选题或完整论文设计

按实际需要逐项询问，不机械问完全部：

1. 研究方向或感兴趣的问题；
2. 研究对象；
3. 学科、学段与场域；
4. 想解决的真实问题；
5. 已有题目或关键词；
6. 可接触的教师、学生、学校或文本材料；
7. 可使用的时间和研究条件；
8. 能接受的方法类型；
9. 已有文献和理论基础；
10. 学校格式、导师要求或明确限制。

### 2. 开题报告

最低需要确认：

- 暂定题目或方向；
- 研究对象与场域；
- 核心研究问题；
- 可获得的数据或材料；
- 研究时间与实施条件；
- 已有文献基础；
- 学校开题格式或栏目要求。

### 3. 文献综述

最低需要确认：

- 综述主题与边界；
- 文献数量和材料类型；
- 是否具备作者、年份、来源等信息；
- 需要矩阵、综述框架、段落、小节还是完整初稿；
- 国内外是否分别呈现；
- 综述最终服务于哪个研究题目。

### 4. 方法与工具设计

最低需要确认：

- 研究问题；
- 研究对象与样本来源；
- 需要描述现状、解释原因、分析文本还是评价实践；
- 可获取的数据；
- 是否能够实施问卷、访谈、观察或文本收集；
- 用户可承担的数据分析难度。

## 七、问题选择优先级

每轮从以下顺序选择最关键的未确认问题：

```text
最终交付物
→ 研究对象与边界
→ 核心问题
→ 现实条件与数据来源
→ 研究类型
→ 理论或分析维度
→ 方法与工具
→ 输出格式与限制
```

不要先询问次要格式，而忽略研究对象、核心问题和数据条件。

## 八、信息校验

进入生成前检查：

1. 用户的研究中心是否清楚；
2. 研究对象和范围是否具体；
3. 研究问题是否能由可获得数据回答；
4. 题目是否预设了无法验证的效果或因果；
5. 理论、维度、方法是否与问题对应；
6. 用户回答之间是否存在冲突；
7. 最终交付物和格式是否明确。

发现冲突时，只询问一个冲突点，例如：

```text
你希望研究“提升效果”，但目前无法实施前后测或对照研究。你更愿意：

A. 保留效果研究，并补充实验条件
B. 改为现状、问题与改进策略研究
C. 改为实践过程或案例研究
D. 暂时不确定
```

## 九、完成条件

满足以下条件后，可询问用户是否生成最终成果：

- 最终目标明确；
- 研究对象和边界基本明确；
- 核心问题已确认；
- 数据或材料来源基本可行；
- 不存在未解决的关键冲突；
- 已达到目标模式或流程的最低输入条件。

提示方式：

```text
关键信息已经基本齐全。我可以据此生成【最终成果】，并把仍不确定的部分单独标注。回复“生成”即可；也可以先回复“查看进度”或“修改：……”。
```

## 十、最终生成规则

生成最终成果时按以下顺序：

1. 简要列出“已确认依据”；
2. 列出“仍待确认或本次采用的假设”；
3. 调用对应单模式或流程生成正式成果；
4. 做题目—问题—数据—方法—章节一致性检查；
5. 不把用户的暂定答案写成已被文献证明的事实；
6. 用户选择“直接生成”时，减少追问，但必须显式标记缺口和假设。

## 十一、避免事项

- 不要一轮提出一长串问题让用户填表；
- 不要重复询问用户已经回答的信息；
- 不要边询问边提前写完整开题报告；
- 不要把引导问题写成考试题或专业术语测验；
- 不要为了凑齐模板强迫用户回答无关信息；
- 不要在关键研究条件不成立时假装已经梳理完成；
- 不要无限提问，达到最低完成条件后应主动进入总结与生成阶段。
