# 完整工作流的引导式入口

## 一、定位

`guided` 不是独立于工作流的新功能，而是完整工作流的一种入口。

用户选择引导式后，Skill 先逐轮收集和校验工作流所需信息；达到最低输入条件后，再执行与直接式完全相同的 `paper-to-note`、`literature-review`、`proposal-design` 或 `thesis-design` 流程。

```text
完整任务
→ 用户选择引导式 / 直接式

引导式
→ 每轮一个关键问题
→ 形成完整输入包
→ 执行目标工作流全部阶段
→ 输出最终成果

直接式
→ 使用现有材料形成输入包
→ 执行目标工作流全部阶段
→ 输出最终成果
```

两种入口不得改变工作流的阶段、质量标准和最终交付物。

## 二、进入引导前

用户提出完整任务但没有说明执行方式时，先提供选择：

```text
你希望怎样完成这项任务？

A. 引导式：我每次只问一个关键问题，逐步梳理清楚后，再执行完整工作流。
B. 直接式：根据现有材料立即执行完整工作流，缺失内容会标注为待确认或有限假设。
```

以下情况不再询问：

- 用户明确要求“一步一步引导”时，直接进入引导式；
- 用户明确要求“直接生成、不要提问、调用完整流程”时，直接进入直接式；
- 用户只要求一个单项结果时，不启动完整工作流选择。

## 三、会话状态卡

每轮内部维护以下状态，不必每次完整展示：

```yaml
guided_session:
  target_pipeline: ""
  final_deliverable: ""
  status: "目标确认"
  confirmed: {}
  tentative: {}
  skipped: []
  conflicts: []
  missing: []
  next_question: ""
  readiness: 0
  ready_to_run_pipeline: false
```

状态只使用：

- `目标确认`；
- `信息收集`；
- `关系校验`；
- `等待执行`；
- `执行工作流`；
- `已完成`。

## 四、第一步：确定目标工作流

用户未明确最终交付物时，第一轮只询问目标：

```text
你希望最后得到什么？

A. 一篇论文的完整解析、筛选与 Obsidian 入库
B. 多篇文献的矩阵、分类综述和综述初稿
C. 从研究方向梳理到完整开题报告
D. 从论文题目梳理到研究问题、方法、目录和写作计划
E. 其他完整成果
```

对应关系：

| 最终目标 | 目标工作流 |
|---|---|
| 单篇论文解析与入库 | `paper-to-note` |
| 多篇文献综述 | `literature-review` |
| 开题报告 | `proposal-design` |
| 毕业论文整体设计 | `thesis-design` |

若用户只需要题目优化、问卷设计或一个综述段落，应退出引导式完整流程，改用对应单模式。

## 五、每轮提问规则

1. 每轮只问一个主问题，不在一个回合堆叠多个独立问题。
2. 优先询问最能影响下一阶段设计的信息。
3. 问题应具体、自然、可回答，不把用户当作研究方法考试对象。
4. 适合时提供 3—6 个选项，并保留“其他”“不确定”“暂时跳过”。
5. 已回答的信息不得重复询问；发现矛盾时只核对一个矛盾点。
6. 用户回答模糊时，先用一句话归纳理解，再询问是否准确。
7. 用户“不确定”时可记录为待确认，继续询问其他关键项。
8. 除非用户要求查看，不要每轮展示完整状态表。
9. 不边询问边反复生成最终成果；先完成输入梳理，再统一执行工作流。

推荐格式：

```text
目前已经确认：……

接下来只确认一件事：……？

A. ……
B. ……
C. ……
D. 其他
E. 暂时不确定
```

## 六、用户控制指令

| 指令 | 行为 |
|---|---|
| `查看进度` | 展示已确认、待确认、冲突和完成度 |
| `修改：字段=内容` | 修改已记录信息，并检查受影响项目 |
| `跳过` | 暂时跳过当前问题，记录为待确认 |
| `不确定` | 记录为不确定，不强迫作答 |
| `直接生成` | 结束提问，切换到直接式并执行同一目标工作流 |
| `重新开始` | 清空状态，重新选择目标工作流 |
| `结束引导` | 停止提问，只总结已梳理信息，不执行工作流 |

`直接生成` 不等于只生成一个简化答案，而是使用当前已收集信息直接执行目标工作流的全部阶段。

## 七、不同工作流的最低输入

### 1. `paper-to-note`

- 论文全文、摘要或可读取材料；
- 是否需要质量筛选；
- Obsidian 字段或用户已有规范（如有）。

### 2. `literature-review`

- 综述主题与边界；
- 文献或文献卡；
- 最终服务的论文题目或研究方向；
- 需要矩阵、框架、小节还是完整初稿；
- 作者、年份、来源等基本信息的完整情况。

### 3. `proposal-design`

- 暂定题目或研究方向；
- 研究对象与场域；
- 想解决的真实问题；
- 可获得的数据或材料；
- 时间和实施条件；
- 已有文献基础；
- 学校开题格式或导师限制（如有）。

### 4. `thesis-design`

- 研究方向或已有题目；
- 研究对象、学科、学段和场域；
- 核心问题；
- 可获取的数据；
- 可接受的方法与分析难度；
- 已有文献或理论；
- 学校论文要求或限制。

最低输入不是固定问卷。已经从上下文确认的信息不得再问。

## 八、问题选择优先级

```text
最终交付物和目标工作流
→ 研究对象与边界
→ 核心问题
→ 现实条件与数据来源
→ 研究类型
→ 理论或分析维度
→ 方法与工具
→ 输出格式与限制
```

不要先问字体、篇幅等次要格式，而忽略研究对象、核心问题和数据条件。

## 九、关系校验

进入工作流前检查：

1. 研究中心是否清楚；
2. 研究对象和范围是否具体；
3. 研究问题能否由可获得数据回答；
4. 题目是否预设无法验证的效果或因果；
5. 理论、维度、方法是否与问题对应；
6. 用户答案之间是否存在冲突；
7. 最终交付物和格式是否明确。

发现冲突时只询问一个冲突点。例如：

```text
你希望研究“提升效果”，但目前无法实施前后测或对照研究。你更愿意：

A. 保留效果研究，并补充实验条件
B. 改为现状、问题与改进策略研究
C. 改为实践过程或案例研究
D. 暂时不确定
```

## 十、切换到完整工作流的条件

满足以下条件后，提示用户可以执行：

- 目标工作流明确；
- 研究对象和边界基本明确；
- 核心问题已确认；
- 数据或材料来源基本可行；
- 不存在未解决的关键冲突；
- 已达到目标工作流的最低输入条件。

提示：

```text
关键信息已经基本齐全。接下来将执行【目标工作流】的全部阶段，并把仍不确定的内容单独标注。回复“执行”即可；也可以先回复“查看进度”或“修改：……” 。
```

用户回复“执行”后，不再继续零散提问，立即运行完整工作流。

## 十一、最终执行规则

1. 形成一个结构化“工作流输入包”；
2. 列出已确认信息、待确认信息和必要假设；
3. 依次执行目标工作流的全部阶段；
4. 每阶段保留中间产物和质量状态；
5. 最终做题目—问题—数据—方法—章节一致性检查；
6. 不把用户暂定答案写成文献已经证明的事实；
7. 若用户中途选择“直接生成”，按直接式规则继续同一工作流。

## 十二、避免事项

- 不让用户一次填写一长串问题；
- 不重复询问已回答的信息；
- 不把引导式变成一个与完整工作流平行的简化功能；
- 不在输入尚未梳理完成时反复生成完整报告；
- 不为了凑齐模板强迫回答无关信息；
- 不无限提问，达到最低条件后主动进入工作流执行；
- 不因选择直接式而省略工作流阶段，只能减少前置提问。
