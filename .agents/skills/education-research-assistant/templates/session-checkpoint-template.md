# 引导会话检查点与恢复模板

## 一、用途

用于长对话中的进度保存、恢复和跨阶段衔接。用户可以要求“保存进度”，得到一份可复制的检查点；后续提供该检查点并说“恢复进度”，即可继续引导或执行工作流。

检查点只保存研究任务所需信息，不复制整段对话。

## 二、保存指令

用户输入：

```text
保存进度
```

输出以下结构：

```yaml
education_research_checkpoint:
  version: "2.6.2"
  checkpoint_id: ""
  target_pipeline: ""
  entry_style: "guided"
  current_status: "信息收集"
  readiness: 0
  output_profile: "standard"
  confirmed:
    final_deliverable: ""
    research_center: ""
    research_object: ""
    scope: ""
    research_type: ""
    data_sources: []
    methods: []
    theory_or_framework: []
    research_questions: []
  tentative: {}
  excluded_options: []
  conflicts: []
  missing: []
  completed_decisions: []
  next_question: ""
  next_action: "continue_guidance"
```

## 三、恢复指令

用户粘贴检查点并输入：

```text
恢复进度
```

恢复时依次完成：

1. 检查 `target_pipeline` 是否存在；
2. 读取已确认、暂定、冲突和缺失信息；
3. 不重复询问已确认问题；
4. 检查检查点内部是否存在逻辑冲突；
5. 继续 `next_question`，或根据当前状态进入工作流；
6. 新信息与检查点冲突时，以用户本轮明确修改为准，并记录变更。

恢复提示：

```text
已恢复【目标工作流】进度。
已确认：……
仍需确认：……
当前完成度：……

接下来只确认一件事：……？
```

## 四、自动检查点

在以下节点可主动生成简短检查点摘要，但不默认输出完整 YAML：

- 完成目标工作流选择；
- 研究对象和数据条件确认后；
- 研究类型确定后；
- 用户准备执行完整工作流前；
- 用户要求暂停时。

只有用户要求“保存进度”时，才输出完整可复制 YAML。

## 五、版本兼容

恢复旧检查点时：

- 缺失新字段：标记为空，不自行编造；
- 字段名称变化：在含义明确时映射；
- 无法识别字段：保留在 `legacy_fields`；
- 目标工作流不存在：询问用户选择当前支持的工作流；
- 检查点内容明显损坏：说明无法可靠恢复，并列出仍可识别信息。

## 六、隐私与范围

检查点不应包含：

- 与研究任务无关的个人信息；
- 用户未要求保存的敏感身份信息；
- 完整论文正文或大段文献原文；
- 密钥、账号或连接凭证。

样本学校和地区如需匿名，应使用用户设定的代号。

## 七、恢复后的执行选择

恢复后用户可以：

- `继续引导`；
- `查看进度`；
- `修改：字段=内容`；
- `直接生成`；
- `重新开始`。

`直接生成` 使用恢复后的输入包，执行同一目标工作流全部阶段。

## 八、禁止事项

- 不声称能够在外部后台永久保存会话；
- 不依赖未提供的历史对话完成恢复；
- 不把完整对话转存为检查点；
- 不在恢复后重新询问全部问题；
- 不将暂定信息恢复为已确认信息。
