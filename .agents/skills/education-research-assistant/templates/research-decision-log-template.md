# 研究决策日志模板

## 一、用途

用于记录引导式或直接式工作流中的关键研究决定，防止题目、问题、方法和目录在后续修改中失去一致性。

决策日志不是一般会议记录。只记录会影响研究设计和最终成果的决定。

## 二、决策表

| 编号 | 决策事项 | 当前决定 | 依据 | 备选方案 | 未采用原因 | 影响范围 | 状态 |
|---|---|---|---|---|---|---|---|
| D-01 |  |  |  |  |  |  | 已确认 |

状态只使用：

- `暂定`；
- `已确认`；
- `需复核`；
- `已替换`；
- `已撤销`。

## 三、应记录的决策

至少包括与任务有关的以下内容：

1. 最终交付物和目标工作流；
2. 论文研究中心；
3. 研究对象、范围和场域；
4. 核心概念及其边界；
5. 研究问题；
6. 研究类型；
7. 理论或分析框架；
8. 数据来源；
9. 方法和工具；
10. 论文目录结构；
11. 关键维度与来源；
12. 用户明确排除的方案。

## 五、变更传播规则

当用户修改一个字段时，必须检查其下游影响：

```text
研究对象变化
→ 样本范围
→ 数据来源
→ 问卷/访谈对象
→ 题目和目录表述

核心概念变化
→ 概念界定
→ 分析维度
→ 研究问题
→ 工具题项
→ 结论边界

研究问题变化
→ 所需证据
→ 方法与工具
→ 数据分析
→ 结果章节

研究类型变化
→ 研究问题表达
→ 方法组合
→ 数据分析
→ 论文目录

数据条件变化
→ 可回答问题
→ 方法可行性
→ 结论强度
```

不得只修改用户点名的一处，而保留明显冲突的下游内容。

## 六、决策冲突表

| 冲突编号 | 冲突内容 | 涉及决策 | 严重程度 | 建议处理 |
|---|---|---|---|---|

严重程度：

- `阻断`：不解决无法继续；
- `重要`：可继续，但最终方案不稳定；
- `一般`：不影响主体，仅需标注。

## 七、最终决策摘要

在执行完整工作流前，形成精简摘要：

```yaml
research_decisions:
  target_pipeline:
  output_profile:

  research_questions: []
  data_sources: []

  unresolved_decisions: []
```

## 八、使用限制

- 不把每一句用户表达都写入决策日志；
- 不把模型建议自动标记为用户已确认；
- 暂定决定必须保留“暂定”状态；
- 用户修改决定后，原决定应标为“已替换”，不要直接删除历史；
- 最终成果只使用当前有效决定；
- 决策日志不能代替证据协议。
