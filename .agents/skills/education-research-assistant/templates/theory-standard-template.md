# 理论基础与分析框架

## 一、任务类型

本次任务：分析现有论文理论 / 为用户研究设计理论框架。

材料状态：

## 二、显性理论识别

| 理论/框架 | 原文位置或来源 | 作者如何使用 | 使用层级 | 判断 |
|---|---|---|---|---|

使用层级只选择：

- 背景性提及；
- 概念解释；
- 生成分析维度；
- 指导工具设计；
- 建立变量关系；
- 解释研究结果；
- 贯穿全文。

不得把背景性提及写成核心理论基础。

## 三、隐含分析逻辑

当原文没有明确理论时，分析其实际使用的概念关系和分类逻辑，并标注“文本归纳”。

| 隐含逻辑 | 文本依据 | 作用 | 是否足以构成分析框架 |
|---|---|---|---|

## 四、理论适配性

| 判断维度 | 问题 | 评价 |
|---|---|---|
| 对象适配 | 理论是否解释当前研究对象 |  |
| 问题适配 | 是否能回答研究问题 |  |
| 层级适配 | 个体、课堂、组织或制度层级是否一致 |  |
| 工具适配 | 是否能转化为问卷、访谈或编码维度 |  |
| 解释适配 | 是否能解释预期数据 |  |
| 简约性 | 是否存在理论堆叠 |  |

总体判断：适配 / 部分适配 / 不适配。

## 五、理论—研究对齐

| 理论概念 | 操作性含义 | 对应研究问题 | 对应维度/变量 | 数据来源 | 使用章节 |
|---|---|---|---|---|---|

无法进入研究问题、工具或结果解释的理论，不建议作为核心理论。

## 六、分析框架构建

框架来源：理论推导 / 文献归纳 / 政策标准 / 混合来源。

| 一级维度 | 二级维度 | 定义 | 来源 | 可观察或可编码表现 | 对应研究问题 |
|---|---|---|---|---|---|

维度之间应相互区分，并共同覆盖研究对象。避免维度概念重叠。

## 七、理论关系图

仅在关系明确时生成。例如：

```mermaid
graph LR
A[理论核心概念] --> B[分析维度]
B --> C[研究工具]
C --> D[数据分析]
D --> E[结果解释]
```

若研究不是变量模型，不强行画因果箭头。

## 九、无核心理论方案

某些文本分析、实践设计或描述性研究可以采用文献归纳的分析框架。此时说明：

1. 为什么不需要强行引入宏大理论；
2. 维度如何从文献、课标或材料中形成；
3. 如何保证维度有依据、可区分、可操作；
4. 框架如何服务研究问题和数据分析。

## 十、风险检查

- [ ] 是否把提及理论当作使用理论；
- [ ] 是否堆叠多个功能重复的理论；
- [ ] 理论是否与研究层级一致；
- [ ] 理论是否转化为实际维度或解释；
- [ ] 是否先有问卷维度再倒找理论；
- [ ] 是否将相关关系画成因果模型；
- [ ] 是否编造理论来源或维度出处。
